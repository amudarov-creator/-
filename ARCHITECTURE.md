# Архитектура MVP

```text
Telegram (aiogram) → handlers/FSM → analytics service → PostgreSQL
                                       ↑                 ↑
                         versioned pure metrics      authorised importer
                                                       ↑
                                         PandaScore / GRID / licensed CSV
```

`data_sources` возвращает исходные записи с ID поставщика. Нормализатор/импортер записывает сущности идемпотентно. `analytics` не вызывает сеть и никогда не выдумывает пропущенное значение. Отчёт обязан хранить фильтры, окно дат, карты, версию формулы и статус полноты (в следующей миграции — таблица `report_runs`). Redis предназначен для кеша запросов и блокировок импорта; он не является источником истины.

## Схема данных

```text
tournaments 1──* matches 1──* map_results 1──* player_map_stats *──1 players
                   │              │                  │
                   └── teams (A/B/winner) ───────────┴── team/opponent
ingestion_runs — provenance and import health
```

Все внешние сущности имеют `(source, source_id)` с уникальным ограничением. `player_map_stats` уникален по `(player_id, map_result_id)`, поэтому повторный import не должен порождать дубль. В `rating_version` обязательно записывается версия рейтинга поставщика; метрики разных версий не смешиваются.

## Границы MVP

Рабочая часть MVP — поиск игрока в загруженных данных, отчёт по картам и чистое аналитическое ядро. Импортер уже делает авторизованный запрос PandaScore и upsert команд; расширение до мап, игроков и их статистики намеренно не заявлено готовым, потому что реальные поля ответа зависят от подключённого тарифа и фида. После подтверждения JSON-образца от лицензированного аккаунта нужно реализовать нормализатор и включить разделы команд/сравнения.

## Формулы 1.0

- `K/D = Σ kills / Σ deaths`; при нулевых смертях результат `NULL`, а не бесконечность.
- `ADR = Σ damage / Σ rounds_played`.
- `Индекс стабильности = max(0, 100 × (1 − σ(rating)/mean(rating)))`; это собственный индекс, не рейтинг HLTV.
- `Изменение формы = mean(rating второй половины) − mean(rating первой половины)` в хронологическом порядке.

Меньше 5 карт — результат не ранжируется; 5–9 — крайне ограниченная выборка; 10–19 — предварительная; по умолчанию 20+ — допустимый минимум для ранжирования. Это предупреждения, а не доказательство статистической значимости.
